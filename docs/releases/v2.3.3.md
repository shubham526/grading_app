# Rubric Grading Tool v2.3.3

## Programming Submission & Autograding

v2.3.3 activates the programming-submission route introduced by the v2.3.2 canonical submission layer and adds a complete instructor-facing Python autograding workflow. The release binds one exact immutable canonical submission attempt to one exact immutable grader bundle, executes that plan inside a hardened Docker container, collects structured public/hidden pytest results, computes deterministic scores, persists every run as immutable evidence, and exposes current-run, batch, results, and history workflows in the desktop application.

### Release scope

- Autograding domain/configuration schema with explicit public/hidden tests, resource limits, test groups, scoring policy, and provenance.
- Validated immutable instructor test-bundle ingestion under the assessment workspace.
- Canonical Python submission adapter supporting active or explicit historical attempts, multi-file submissions, required files, safe logical paths, and exact SHA-256 verification.
- Stable `ExecutionPlan` binding exact submission bytes to exact grader bytes before execution.
- Execution-backend abstraction that explicitly forbids direct host execution.
- Docker-based Python sandbox with:
  - network disabled,
  - read-only root filesystem,
  - read-only submission/grader/runtime inputs,
  - dropped Linux capabilities,
  - `no-new-privileges`,
  - unprivileged UID/GID,
  - memory/CPU/PID limits,
  - bounded stdout/stderr capture,
  - outer wall timeout,
  - verified container/staging cleanup.
- Dedicated Python 3.12 + pytest 9.1.1 grading-runtime image definition under `docker/autograding/python312-pytest/`.
- Structured pytest execution using a machine-readable JSON protocol instead of console-text scraping.
- Public/hidden test visibility, per-test timeout, student syntax preflight, collection/selection diagnostics, and student-safe hidden-test redaction.
- Deterministic scoring for explicit per-test points and equal-within-group configurations.
- Explicit separation between student-attributable failures and grader/infrastructure failures so infrastructure errors never silently become student zeros.
- Immutable autograding run history preserving plan, runtime provenance, test results, scores, stdout/stderr evidence, and reruns.
- Instructor report, student-safe report, and compact history-report builders.
- Qt-free `AutogradingService` composing planning, execution, scoring, and persistence.
- Desktop UI under **Tools → Programming Autograding** for configuration, current-submission grading, batch grading, results, and history.
- Background worker execution so Docker grading does not block the Qt GUI thread.

### Safety boundaries retained in v2.3.3

v2.3.3 deliberately does **not** execute student code directly in the grading-app Python environment. If Docker is unavailable, the app reports the autograding runtime as unavailable; it does not fall back to `subprocess` execution on the host.

The release also retains these boundaries:

- Student execution network access remains disabled.
- The app does not mount the instructor home directory, grading-app repository, SSH keys, Canvas credentials, Docker socket, or full Grades + Evidence Folder into the student container.
- The app does not auto-pull or auto-build grading images during a grading run.
- `requirements.txt` may be preserved/validated in a grader bundle but is not automatically installed during student execution.
- Hidden-test raw IDs, pytest node IDs, traceback, hidden stdout/stderr, grader hashes, and container provenance are excluded from student-safe reports.
- A run-level timeout or infrastructure/protocol anomaly remains review-required rather than being converted to an automatic numeric grade.
- Programming-autograding scores are persisted as separate immutable evidence and do not silently overwrite the app's manual rubric criterion scores.
- Cooperative batch cancellation waits for the current student's container to finish or time out so the established cleanup boundary is preserved.

### Runtime model

The grading app itself may continue to run under its existing Python environment. Student Python executes in the separately built grading image:

```text
macOS / Windows / Linux host
└── grading_app desktop process
    └── Docker Engine / Docker Desktop
        └── grading-app-python312-pytest:9.1.1
            ├── read-only student submission
            ├── read-only grader bundle
            ├── read-only structured runtime
            ├── ephemeral output
            └── no external network
```

Build the release runtime once from the repository root:

```bash
docker build \
  -t grading-app-python312-pytest:9.1.1 \
  docker/autograding/python312-pytest
```

Verify:

```bash
docker run --rm --network none --pull=never \
  grading-app-python312-pytest:9.1.1 \
  python -c 'import pytest; print(pytest.__version__)'
```

Expected output:

```text
9.1.1
```

### Workspace layout

Autograding data is stored alongside the assessment workspace while remaining separate from canonical submission evidence:

```text
<Grades + Evidence Folder>/
├── submission_evidence/
│   └── canonical/...
└── autograding/
    └── <assessment>/
        ├── bundles/
        │   └── <immutable grader bundle>/...
        └── runs/
            └── <student>/
                ├── index.json
                └── <run-id>/
                    ├── run.json
                    ├── plan.json
                    ├── pytest_results.json
                    ├── scoring.json
                    └── evidence/
                        ├── execution_stdout.txt
                        └── execution_stderr.txt
```

Each rerun receives a new run ID. Earlier runs are not overwritten.

### Scoring semantics

The instructor configuration, not runtime-reported point values, is authoritative.

Default v2.3.3 outcome policy:

- `passed`, `xfail`, `xpass` → full configured credit.
- student-attributable `failed`, `error`, and per-test `timeout` → zero configured credit.
- `pending`, `skipped`, `infrastructure_error`, and synthetic run-level timeout → unresolved/review-required.

If any run-level structural/infrastructure condition requires review, `final_score` remains `None` even when some individual test points are known.

### Instructor UI

The release adds:

```text
Tools
└── Programming Autograding
    ├── Configure Autograder…
    ├── Grade Current Submission
    ├── Grade All Active Submissions…
    └── Autograding History…
```

The configuration dialog imports/selects an immutable grader bundle and verifies the local Docker pytest runtime. Current grading confirms the student, active attempt, grader bundle, and runtime before launching. The results dialog shows instructor diagnostics and scores. The history dialog reopens integrity-verified immutable runs. Batch grading continues past individual student errors and supports cooperative cancellation.
