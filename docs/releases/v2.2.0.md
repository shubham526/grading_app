# Rubric Grading Tool v2.2.0 Release

**Version:** 2.2.0  
**Release focus:** LaTeX/PDF submission ingestion, persistent submission evidence, scan transcription, and question-centric grading integration  
**Status:** Feature-complete; final release acceptance requires a successful end-to-end scanned-PDF transcription test on an available GPU

---

## 1. Overview

v2.2.0 extends the Rubric Grading Tool from a grading-interface application into an evidence-aware submission ingestion system.

The release introduces a complete submission pipeline for:

- canonical LaTeX submissions,
- explicit PDF-accommodation submissions,
- deterministic text extraction from digital PDFs,
- page rendering for scanned PDFs,
- assistive vision-language-model transcription for image-only scans,
- persistent submission evidence and provenance,
- question-specific student-response extraction,
- optional instructor reference solutions,
- and direct integration of all of the above into the question-centric grading workflow introduced in v2.1.0.

The primary design goal is to preserve a clear distinction between **authoritative student evidence** and any **derived machine-readable representation** used for convenience or future automated grading.

## 2. Release Principles

### 2.1 Authoritative source remains explicit

The system does not silently replace original student work with extracted or generated text.

For normal submissions:

```text
main.tex
   ↓
canonical student submission
   ↓
compiled PDF for human viewing
   ↓
parsed machine-readable text
```

For PDF accommodations:

```text
original.pdf
   ↓
authoritative student evidence
```

If the PDF contains selectable text:

```text
original.pdf
   ↓
PyMuPDF extraction
   ↓
machine-readable student response
```

If the PDF is scanned/image-only:

```text
original.pdf
   ↓
200-DPI page images
   ↓
assistive VLM transcription
   ↓
machine-readable student response
```

The original PDF remains authoritative in both cases.

### 2.2 No silent correction or inference

Machine-readable extraction and transcription must preserve what the student submitted.

For scan transcription:

- do not solve the problem,
- do not correct the student's answer,
- do not infer missing text,
- preserve mathematical notation where possible,
- use `[ILLEGIBLE]` when text cannot be read confidently.

### 2.3 Provenance is first-class data

Every machine-readable representation records its origin.

Examples include:

- LaTeX source parsing,
- digital-PDF text extraction,
- scanned-PDF AI transcription,
- transcription model,
- prompt version,
- source-page hashes,
- cache status,
- authoritative/assistive flags,
- per-page transcription status.

This is required groundwork for later AI-assisted grading.

## 3. Supported Submission Modes

### 3.1 Normal LaTeX submission

Normal submissions are expected to use LaTeX.

Canonical input:

```text
student_id/
└── main.tex
```

The system:

1. discovers the student submission,
2. validates LaTeX input,
3. compiles it securely,
4. produces a PDF for the grader,
5. parses question-specific student responses,
6. persists source and derived evidence.

Student-provided PDFs are not treated as canonical normal submissions.

### 3.2 PDF accommodation

PDF-only submission is supported through an explicit accommodation path.

The UI uses **Add PDF Accommodation** to distinguish this workflow from normal LaTeX ingestion.

Only generic submission metadata is persisted:

```json
{
  "submission_mode": "pdf_accommodation",
  "accommodation_mode": true
}
```

The application does **not** persist disability, medical, diagnostic, or accommodation-reason information.

### 3.3 Digital/selectable PDF

For a text-bearing PDF:

- the original PDF remains authoritative,
- PyMuPDF extracts selectable text,
- no OCR or VLM is required,
- extracted text is used as the machine-readable representation,
- question-specific responses are derived from the extracted text.

### 3.4 Scanned/image-only PDF

For a scanned PDF:

- the original PDF remains authoritative,
- pages are rendered to deterministic PNG images at 200 DPI,
- a vision-language model may transcribe the rendered pages,
- transcription is explicitly marked assistive and non-authoritative,
- transcription provenance is retained,
- future AI grading must not treat transcription as equivalent to the original scan without review.

## 5. Question-Specific Student Responses

v2.2.0 connects submission evidence directly to the question-centric grading workflow.

The UI provides a **Student Response** action.

This replaces the earlier ambiguous **Answer** label.

`Student Response` means:

> the machine-readable response extracted for the currently selected student and currently selected question.

It does **not** mean the expected/correct solution.

Examples:

```text
LaTeX
main.tex
   ↓
question parser
   ↓
Student Response for Q1
```

```text
Digital PDF
original.pdf
   ↓
PyMuPDF text extraction
   ↓
question parser
   ↓
Student Response for Q1
```

```text
Scanned PDF
original.pdf
   ↓
page images
   ↓
VLM transcription
   ↓
question parser
   ↓
Student Response for Q1
```

## 6. Instructor Reference Solutions

v2.2.0 adds optional assignment-level reference solutions.

The preferred format is:

```text
solution.tex
```

LaTeX is recommended because it provides:

- deterministic machine-readable text,
- reliable mathematical notation,
- clean question splitting,
- straightforward compilation to PDF,
- better future grounding for LLM-assisted grading.

Digital/selectable PDF is supported as a fallback.

### 6.1 Reference-solution behavior

The main UI provides:

```text
Load Reference Solution
```

The grading workspace provides:

```text
Reference Solution
```

When the grader is on Q1, the reference-solution action shows the Q1 reference solution when one can be extracted. Q2 shows Q2, and so on.

The reference solution is:

- assignment-level,
- optional,
- separate from student evidence,
- never silently used to change a score,
- currently a human-grading reference,
- available for future LLM-assisted grading as an explicit grounding source.

### 6.2 Source hierarchy

Recommended:

```text
1. LaTeX reference solution
2. Digital/selectable PDF reference solution
3. Scanned reference solution only as a last resort
```

A scanned reference solution would introduce transcription uncertainty into what is intended to represent expected/correct work.

## 7. Scan Transcription

### 7.1 Default model

Production/default handwriting transcription model:

```text
gemma4:31b
```

Fallback/alternate:

```text
qwen3-vl:8b-instruct
```

The established handwriting benchmark ranking used for this release was:

1. Gemma 4 31B
2. Qwen3-VL-8B Instruct
3. Gemma 4 26B
4. PaddleOCR-VL-1.6
5. Gemma 4 12B

### 7.2 Transcription prompt

Prompt version:

```text
1.0
```

The transcription instruction requires faithful preservation of visible text, mathematics, asymptotic notation, equations, pseudocode, and question headings.

It explicitly prohibits:

- solving,
- correction,
- missing-text inference.

Unreadable content should be represented as:

```text
[ILLEGIBLE]
```

### 7.3 Page rendering

Scanned PDFs are rendered internally before inference.

The user does not need to manually convert PDFs to images.

Pipeline:

```text
scanned PDF
   ↓
PyMuPDF
   ↓
page_001.png at 200 DPI
   ↓
VLM
   ↓
transcription
```

### 7.4 Transcription statuses

Supported status categories include:

```text
successful
unavailable
model_load_failure
model_load_timeout
inference_failure
inference_timeout
empty_output
generation_limit
degenerate_repetition
```

### 7.5 Timeout handling

v2.2.0 separates several failure modes that were previously conflated.

Representative policy:

```text
connection check      → short timeout
cold model load       → long timeout
page inference        → separate inference timeout
```

The UI reports meaningful states such as:

```text
Loading gemma4:31b...
```

and, on failure:

```text
Transcription failed · model loading timed out
```

A **View Details** action exposes the recorded failure reason and provenance.

### 7.6 Shared-GPU behavior

The grading application does not manage or evict unrelated Ollama models.

If the configured transcription model cannot be loaded because GPU memory is occupied, the transcription may fail or time out without affecting the authoritative submission evidence.

The grader can retry later when resources are available.

---

## 8. Transcription Cache

Successful page transcription may be cached.

The cache key incorporates provenance such as:

- backend identity,
- model,
- prompt version,
- source PDF hash,
- rendering DPI,
- page hashes.

Cache-first behavior avoids unnecessary re-inference.

A valid cached result can therefore be reused without loading the VLM again.

Cache eligibility requires usable transcription output.

## 9. Grading Workspace Redesign

v2.2.0 introduces a document-first, Gradescope-style grading workspace.

Primary layout:

```text
┌──────────────────────────────┬──────────────────────────────┐
│                              │                              │
│      STUDENT SUBMISSION      │         GRADING — Q1         │
│                              │                              │
│      compiled/original PDF   │   rubric criterion           │
│                              │   score                      │
│                              │   comments                   │
│                              │                              │
│                              │   Question Scores Summary    │
│                              │                              │
└──────────────────────────────┴──────────────────────────────┘
```

### 9.1 Draggable splitters

Two independent splitters are provided.

Vertical allocation:

```text
setup / context
      ↕
submission + grading workspace
```

Horizontal allocation:

```text
student submission
      ↔
grading controls
```

Splitter handles are intentionally visible and easier to target than Qt's default native splitter handles.

Splitter state is persisted.

Old vertical-layout state is versioned separately so legacy saved settings cannot silently restore the wrong orientation.

### 9.2 Question Scores Summary

The question-score summary remains inside the grading side.

Collapsed state:

```text
Question Scores Summary            [ Show ▼ ]
```

Expanded state:

```text
Question Scores Summary            [ Hide ▲ ]
```

The control was intentionally made visually prominent after usability testing showed that a small disclosure arrow was too easy to miss.

### 9.3 Workspace pop-out

The workspace can be popped out as a complete grading window.

This moves the actual live:

```text
Submission | Grading
```

container into a top-level window.

It does not create a duplicate copy of grading controls.

Therefore there remains only one:

- PDF viewer,
- score state,
- comments state,
- question-summary state,
- submission state.

The popped-out workspace supports grading/navigation actions and can be reattached to the main window.

### 9.4 Focus mode

Focus mode remains available as a reading-oriented secondary workflow.

Normal grading does not require focus or pop-out mode.

## 11. Background Work and UI Responsiveness

Long-running submission operations are executed through worker infrastructure rather than blocking the main Qt event loop.

Operations include:

- LaTeX compilation,
- PDF ingestion,
- page rendering,
- scan transcription,
- transcription refresh,
- Ollama connection/model checks.

Request IDs are used to protect against stale worker results being applied after the user changes student/question context.

The grading application remains usable when the external Ollama service is unavailable.

## 12. Ollama Configuration

The application treats Ollama as an optional external inference service.

Typical local endpoint when using an SSH tunnel:

```text
http://127.0.0.1:11435
```

Default model:

```text
gemma4:31b
```

Only endpoint/model configuration is stored.

SSH credentials are not stored by the grading application.

Example tunnel:

```bash
ssh -N -L 11435:127.0.0.1:11434 <gpu-host>
```

## 13. Security and Safety

### 13.1 LaTeX compilation

LaTeX compilation is treated as untrusted-input processing.

The ingestion pipeline performs safety validation and uses controlled compilation rather than arbitrary shell execution.

### 13.2 Evidence integrity

Persistent evidence includes hashes so stored evidence can be verified.

Symlink-based source substitution is rejected.

Writes are performed atomically where appropriate.

### 13.3 Accommodation privacy

The system stores only operational submission-mode flags.

It does not store:

- medical diagnoses,
- disability details,
- accommodation reasons,
- health information.

## 14. Future Automatic-Grading Interface

v2.2.0 intentionally prepares data structures for later AI-assisted grading without implementing automatic scoring in this release.

Future model input can be constructed from:

```text
Student Response
      +
Rubric criterion
      +
optional Reference Solution
      +
submission provenance
```

The provenance determines how much trust should be placed in the machine-readable student response.

### 14.1 LaTeX student submission

Preferred machine-readable source:

```text
canonical LaTeX
```

### 14.2 Digital PDF

Preferred machine-readable source:

```text
deterministically extracted PDF text
```

### 14.3 Scanned PDF

Machine-readable source:

```text
assistive VLM transcription
```

For scanned work, future AI-assisted grading must explicitly communicate that:

- transcription may contain errors,
- the original scan is authoritative,
- the grader should be able to inspect the source evidence.

## 18. Known Operational Limitations

### 18.1 VLM transcription requires sufficient GPU resources

The default `gemma4:31b` model is large.

On a shared GPU, model loading may fail or time out when VRAM is occupied by other workloads.

This does not affect:

- original submission evidence,
- PDF rendering,
- deterministic digital-PDF extraction,
- manual grading.

### 18.2 Scan transcription is not authoritative

Even successful VLM transcription can contain errors.

The scan remains the authoritative submission.

### 18.3 Reference solution is advisory in v2.2.0

The reference solution is available to the human grader but does not automatically assign or recommend scores in this release.

### 18.4 Normal PDF submission is intentionally not the default workflow

Normal submissions remain LaTeX-first.

PDF-only ingestion is an explicit accommodation path.

## 22. Summary

v2.2.0 establishes the submission-evidence layer required for the next generation of the Rubric Grading Tool.

The key architectural boundary is:

```text
authoritative evidence
        ≠
machine-readable representation
```

That distinction is preserved across LaTeX, digital PDFs, and scanned PDFs.

For human grading, v2.2.0 provides a document-first submission-and-rubric workspace.

For future AI-assisted grading, it provides:

- question-specific student responses,
- optional reference solutions,
- deterministic provenance,
- scan-transcription provenance,
- evidence persistence,
- and an explicit trust boundary between original student work and derived text.

This allows later grading automation to build on v2.2.0 without sacrificing inspectability, provenance, or human review.
