# v2.3.4.1 — Dual-Mode Grading Interface

v2.3.4.1 introduces explicit Written / Text and Programming grading workspaces
inside one application while preserving the existing grading, submission,
provenance, and autograding backends.

## Highlights

### Shared Assessment Home

The application now starts at **Assessment Home**. Instructors configure the
common assessment context once:

- rubric / assessment definition;
- roster;
- Grades + Evidence workspace.

After shared setup is complete, the instructor can enter either **Written /
Text** or **Programming** directly. Programming no longer requires entering the
Written grader first merely to initialize shared state.

### Written workspace isolation

The mature Written grading interface is preserved behind a dedicated
`WrittenGradingWorkspace` boundary. Shared setup controls are removed from the
Written toolbar so the workspace contains mode-specific grading operations
rather than application initialization.

Existing Written behavior remains the compatibility target, including manual
rubric grading, student/question navigation, save/resume, PDF/LaTeX evidence,
submission history, similarity review, reporting, and ABET workflows.

### Programming dashboard

Programming mode now has a dedicated roster/batch-centric dashboard with:

- **Configure Autograder**;
- **Import Submissions**;
- **Check Runtime**;
- **Grade Selected**;
- **Grade All**;
- **Run History**.

The dashboard displays student, active attempt, status, score, last run, and a
Latest Result summary. It reuses the v2.3.3 autograding services rather than
implementing a parallel execution/scoring stack.

### Attempt-aware result display

Programming results are matched to the exact active canonical submission. If a
new attempt is imported, an older attempt's score is not shown as though it
belongs to the new code. The new attempt remains **Not graded** until it has its
own run.

### Safer mode transitions

**File → Assessment Home…** is the common navigation path between workspaces.

- Unsaved Written work uses the established **Save / Discard / Cancel** guard.
- Active Programming grading/runtime/batch operations block mode exit until the
  operation finishes.
- Shared assessment state remains available when switching modes.

## Compatibility

v2.3.4.1 intentionally preserves:

- v2.3.2 canonical submission/provenance behavior;
- v2.3.3 Python/Docker autograding bundle validation;
- isolated execution and resource controls;
- structured pytest results;
- public/hidden test semantics and student-safe redaction;
- deterministic scoring;
- immutable autograding run history;
- manual Written scoring behavior.

Programming scores remain separate from manual rubric grades. This release does
not automatically merge or publish autograding scores.

## Test / release gate

Before tagging, run:

```bash
python -m unittest discover -s src/tests -p 'test_*_v2341.py' -v
python -m unittest discover -s src/tests -p 'test_*_v233.py'
python -m pytest src/tests -q
python -c "import src; assert src.__version__ == '2.3.4.1'; print(src.__version__)"
```

Manual PyQt acceptance is also required because this release changes top-level
application navigation.

## Out of scope

This release does not add:

- Overleaf / LaTeX project ZIP ingestion (planned for v2.3.4.2);
- Canvas synchronization/publishing (planned for v2.3.6.x);
- structured regrade adjudication (planned for v2.3.5);
- LLM-assisted grading;
- automatic programming-score merge into manual rubric grading.
