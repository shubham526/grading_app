# Rubric Grading Tool v2.2.1 Release

**Version:** 2.2.1  
**Release title:** Master ABET Evidence Export  
**Release focus:** Semester-wide, auditable ABET evidence export across assignments and students  
**Status:** Finalized after backend, CLI, UI, regression, and manual acceptance verification

---

## 1. Overview

v2.2.1 adds a **Master ABET Evidence Export** to the Rubric Grading Tool.

The release turns the grading data already collected by earlier versions into a clean, auditable, semester-wide evidence sheet suitable for:

- ABET documentation,
- course and program-outcome auditing,
- assignment-level evidence review,
- semester-level evidence review,
- coordinator sharing,
- archival,
- reproducibility,
- and later report regeneration.

The release does **not** change grading behavior, scoring formulas, ABET aggregation logic, or submission parsing.

Its primary design principle is:

```text
Grade normally
    ↓
save final human-approved assessment data
    ↓
export transparent row-level evidence
```

Each master evidence row represents:

```text
student × assignment × rubric criterion
```

## 5. Canonical Score and Metadata Semantics

v2.2.1 preserves the final human-approved assessment state.

The saved assessment criterion is primary for:

```text
points_awarded
points_possible
selected
counted
saved outcome mappings
saved assessment tags
saved question metadata
```

The rubric is joined by stable criterion ID and is used to fill metadata missing from older assessment snapshots.

Conceptually:

```text
Saved assessment criterion
    ↓ primary source for historical/final grading state

Rubric criterion
    ↓ stable-ID lookup
    ↓ fills missing legacy metadata

Master Evidence Row
```

This design prevents the export from silently disagreeing with historical ABET calculations based on the saved assessment.

Assessment-only historical criteria are preserved and warned rather than dropped.

Rubric-only criteria can appear under the `all` evidence policy even when no saved criterion score exists.

## 6. Evidence Policies

The export supports:

```text
counted_only
selected_only
all
```

### counted_only

Exports evidence rows that count under the existing grading/ABET selection logic.

### selected_only

Exports selected evidence, including rows selected but not ultimately counted.

### all

Exports every rubric criterion/evidence unit available.

### Include excluded rows

The UI and CLI also support:

```text
include_excluded = true
```

This keeps rows excluded by the selected evidence policy while retaining their actual:

```text
Selected
Counted
Evidence Policy
```

values.

This makes it possible to audit both included and excluded evidence without changing the grading policy.

---

## 7. Legacy Selected/Counted Behavior

Older assessment JSON files may not contain explicit:

```text
selected
counted
```

flags.

The existing scoring behavior historically treats missing values as enabled/default-true for evidence-policy purposes.

v2.2.1 preserves that compatibility for filtering.

However, the exported row does **not** fabricate explicit historical values.

Instead:

```text
Selected = blank/None
Counted  = blank/None
```

and warnings are emitted:

```text
missing_selected_flag
missing_counted_flag
```

This preserves existing behavior while remaining transparent about the original saved data.

---

## 8. Percentage Calculation

Criterion percentage is calculated as:

```text
points_awarded / points_possible × 100
```

If:

```text
points_possible == 0
```

then:

```text
Percentage = blank / None
```

No division by zero occurs.

---

## 9. Performance Bands

If a compatible outcome profile is available, row percentage may be mapped to the profile-defined performance band.

Example:

```text
8 / 10
→ 80%
→ adequate
```

At criterion-row level:

```text
Meets Target = blank / None
```

unless target semantics are explicitly applicable.

Outcome-level target checks remain the responsibility of the existing assignment and semester ABET reports.

---

## 10. Missing Data and Warnings

Missing optional data does not normally abort the export.

The exporter tolerates missing:

- student name,
- student ID,
- question ID,
- criterion description,
- outcome mappings,
- assessment tags,
- submission metadata,
- hashes,
- selected/counting flags,
- assignment date,
- assignment type.

Instead, blank values are exported and structured warnings are collected.

Representative warning codes include:

```text
missing_student_id
missing_student_name
missing_question_id
missing_outcome_mapping
missing_points
missing_submission_meta
missing_selected_flag
missing_counted_flag
assessment_file_unreadable
rubric_criterion_not_found
```

Warnings contain available provenance such as:

```text
assignment_id
student_id
criterion_id
assessment_file
message
```

so they can be audited in the UI and exported workbook.

Critical missing files remain fatal where appropriate, such as a missing required rubric or assessment directory.

## 11. Assignment-Level Evidence Generation

The assignment-level backend combines:

```text
rubric
+
assessment directory
+
assignment metadata
+
course metadata
+
evidence policy
```

into normalized evidence rows.

Public backend behavior supports:

```python
build_master_evidence_rows_for_assignment(...)
collect_master_evidence_for_assignment(...)
```

The `collect_...` form additionally returns structured warnings.

The assignment builder:

- loads saved assessment JSON files,
- ignores unrelated existing ABET report JSON files,
- joins saved criteria to rubric criteria by stable ID,
- preserves historical assessment-only criteria,
- supports old assessments missing newer fields,
- extracts optional submission metadata,
- applies the selected evidence policy.

---

## 12. Semester-Level Evidence Generation

Semester export reuses the assignment builder rather than duplicating policy logic.

Conceptually:

```text
semester config
    ↓
assignment 1 → assignment builder
assignment 2 → assignment builder
assignment 3 → assignment builder
    ↓
combined semester rows
+
combined warnings
```

Supported semester-config naming includes both the existing application schema and the design-document aliases.

Examples:

```text
assessments
assessment_id
assessment_name
assessment_dir
```

and:

```text
assignments
assignment_id
assignment_title
assessments_dir
```

Relative rubric and assessment paths are resolved relative to the semester config.

Assignments with:

```text
include_in_abet = false
```

remain excluded from semester master evidence generation.

## 13. Submission Metadata Integration

When v2.2.0 submission metadata is available, rows may include:

```text
Submission Source
Submission Latex File
Submission PDF File
Submission Latex SHA256
Submission PDF SHA256
```

Supported examples include:

```text
source_used = latex
source_used = pdf_accommodation
```

For LaTeX submissions:

- canonical `.tex` path/hash can be included,
- compiled PDF metadata can be used as the available PDF representation.

For explicit PDF accommodation:

- original PDF path/hash is preferred.

If `submission_meta` is absent:

```text
submission fields = blank
```

and the export emits:

```text
missing_submission_meta
```

rather than failing.

## 16. XLSX Export

The XLSX output is:

```text
master_abet_evidence.xlsx
```

The workbook contains:

```text
Evidence Rows
Outcome Summary
Assignment Summary
Warnings
README
```

### Evidence Rows

Contains the complete normalized evidence table.

Features include:

- stable headers,
- frozen header row,
- filtering,
- readable wrapped text,
- numeric percentage cells,
- semicolon-separated outcome/tag values.

### Outcome Summary

Contains summary fields such as:

```text
Outcome
Rows
Students
Total Earned
Total Possible
Average %
```

If the same outcome appears in both `program_outcomes` and `abet_outcomes`, the criterion is not double-counted for that outcome.

### Assignment Summary

Contains:

```text
Assignment
Rows
Students
Criteria
Outcomes Covered
Average %
```

### Warnings

Contains structured export warnings.

The sheet exists even when the clean export has no warnings.

### README

Explains:

- evidence-row semantics,
- evidence policy,
- selected/counting fields,
- optional submission metadata,
- criterion-level target semantics.

If spreadsheet support is unavailable, CSV/JSON remain usable and XLSX can be cleanly reported as unavailable.

## 21. UI Manual-Acceptance Fixes

Manual acceptance identified three usability/workflow issues that were fixed before release.

### 21.1 Result-message truncation

Long output paths caused the completion message to be clipped.

Fix:

- result summary now uses a scrollable viewport,
- long paths remain accessible,
- warnings count remains visible,
- result action buttons remain reachable.

### 21.2 Single-assignment dialog height

Single-assignment mode could exceed available screen height and hide the Export button.

Fix:

- dialog is resizable,
- main form is vertically scrollable,
- Close/Export remain pinned and reachable.

### 21.3 Student submission synchronization

In student-by-student mode, submission evidence did not always appear immediately after loading student data.

Previously, switching to question-by-question mode triggered the synchronization.

Fix:

- current roster/student identity is synchronized in student-centric mode,
- submission evidence is refreshed when roster/assessment context is loaded,
- switching grading modes is no longer required to make the current submission appear.

These fixes were verified manually before release finalization.

## 26. Backward Compatibility

v2.2.1 is designed to tolerate older assessment files.

Older files may be missing:

```text
question_id
selected
counted
submission_meta
file hashes
some outcome mappings
student_name
```

The exporter:

- uses stable-ID rubric lookup when possible,
- fills safe missing metadata from the rubric,
- preserves historical assessment snapshots,
- applies existing legacy selected/counted semantics,
- emits warnings,
- avoids crashing on optional missing data.

Existing assignment and semester ABET reports are not changed.

---

## 27. Non-Goals and Safety Boundary

v2.2.1 does not make new grading decisions.

It does not:

```text

change points_possible
change selected/counting state
change ABET evidence policy
change outcome aggregation
change performance-band definitions
infer missing grades
perform LLM grading
perform similarity/plagiarism review
```

The release exports the final saved state in a more inspectable form.

## 31. Summary

v2.2.1 makes ABET evidence collection a natural byproduct of normal grading.

The central workflow is now:

```text
ABET-aware rubric
    ↓
normal grading
    ↓
final saved assessments
    ↓
Master ABET Evidence Export
    ↓
CSV / JSON / XLSX
    ↓
assignment or semester inspection
    ↓
archival / ABET review
```

The release preserves the most important architectural boundary:

```text
reporting
    ≠
scoring
```

v2.2.1 does not change what a student earned or what evidence counts.

Instead, it provides a normalized, transparent, auditable representation of the grading and outcome data already approved by the instructor.

This completes the reporting/evidence layer needed before moving on to later analysis features such as v2.3.0 Submission Similarity Review.
