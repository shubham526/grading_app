# Rubric Grading Tool v2.3.2

## Submission Core & Provenance Foundation

v2.3.2 introduces a source-agnostic canonical submission layer underneath the existing grading workflow. The release preserves the v2.2 `ParsedSubmission` interface used by grading, similarity review, and assessment evidence while adding immutable source artifacts, attempt history, provenance, safe local importing, backward-compatible legacy migration, and a user-facing import/history workflow.

### Release scope

- Canonical `Submission`, `ArtifactFile`, external-reference, derived-artifact, and import-domain models.
- Immutable filesystem-backed canonical repository under `submission_evidence/canonical/`.
- SHA-256 provenance for committed originals.
- Multiple artifacts per logical submission.
- Multiple attempts per student and assessment, with one mutable active-attempt pointer and immutable historical attempt manifests/artifacts.
- Source-adapter abstraction and local file/directory adapter.
- Conservative roster matching with explicit manual resolution for ambiguous identities.
- Duplicate classification and deterministic attempt assignment.
- Canonical artifact routing into the existing v2.2 LaTeX/PDF parser stack.
- Non-destructive v2.2 evidence migration and canonical linkage persistence.
- `SubmissionController` history awareness while retaining `ParsedSubmission` as the grading-facing state.
- `Import Submissions` preview/commit workflow and `Submission History` UI.
- Background import hashing/copying/parsing so the GUI thread is not used for artifact I/O.

### Safety boundaries retained in v2.3.2

v2.3.2 stores future submission formats without prematurely processing them:

- Python artifacts are preserved but never executed. Programming execution/autograding belongs to v2.3.3.
- ZIP and PDF+ZIP LaTeX-project artifacts are preserved but never extracted. Project parsing belongs to v2.3.4.
- PDF-only written work is not silently treated as an accommodation. The explicit PDF-accommodation path remains required.
- Canonical originals are never overwritten when a new attempt arrives.
- Ambiguous student identity is never silently guessed.
- Canonical artifact hash/size verification occurs before supported parsing by default.
- Failed historical-attempt parsing does not change the active-attempt pointer.

### Grading-workflow polish

The final v2.3.2 acceptance pass also hardens the everyday manual-grading workflow:

- Student-by-student mode now has the same roster dropdown and previous/next navigation available in question-by-question mode.
- Student-mode navigation loads each student's saved assessment and submission evidence rather than changing only the visible name.
- Dirty student-mode work is persisted before moving to another student, switching workflows, or closing the application.
- `Save + Next Student` saves the full current assessment before advancing.
- `Save Assessment` always means a complete current-student save in either workflow; question-mode incremental saving remains explicitly `Save Question` / `Save + Next`.
- `Save Assessment As…` remains available from the compact save-options menu.
- Incomplete grading progress can be saved in either workflow; saving is not treated as final-submission validation.
- Question-centric grading sessions retain an assessment-scoped workspace checkpoint so reopening can resume at the exact prior question and student.
- The primary toolbar is reduced to `Load Rubric` and `Import Submissions`; workspace/roster/reference/accommodation setup, reports, legacy loading, and settings are grouped into compact menus.
- Assessment/rubric/workspace context is consolidated into a compact strip and the grading-configuration summary is shown inline, leaving more vertical room for the submission and grading panes.

### Compatibility

The legacy v2.2 evidence layout remains readable and is never destructively moved or deleted by migration. Existing assessment JSON continues to expose exactly two submission-supporting top-level fields:

- `submission_meta`
- `extracted_answers`

When canonical linkage is available, `submission_meta` additionally records the canonical submission ID, assessment ID, attempt, source system, artifact IDs, and canonical-store schema information. Grading math, rubric semantics, similarity scoring, ABET calculations, and existing `ParsedSubmission` consumers are outside the behavioral scope of this release.

### Canonical repository shape

```text
submission_evidence/
├── <legacy v2.2 student evidence remains supported>
└── canonical/
    └── <assessment>/
        └── <student>/
            ├── index.json
            ├── <submission-id>/
            │   ├── submission.json
            │   ├── originals/
            │   └── derived/
            └── <submission-id>/
                └── ...
```

`submission.json` and committed files under `originals/` are immutable. `index.json` contains the historical list and current `active_submission_id`.

### Release validation

The v2.3.2 acceptance suite covers:

1. First-attempt import for multiple students.
2. Changed source creating a second attempt while attempt 1 remains byte-for-byte unchanged.
3. Repository close/reopen preserving history and active attempt.
4. Exact re-import being classified as a duplicate instead of silently creating another attempt.
5. PDF+ZIP being preserved as one two-artifact logical submission without extraction.
6. Python being preserved without execution.
7. Ambiguous identity requiring manual mapping.
8. Canonical linkage remaining inside the established `{submission_meta, extracted_answers}` assessment contract.
9. Canonical manifest/index JSON surviving repository restart.
