# v2.3.4.2 — Overleaf / LaTeX Project ZIP Ingestion

v2.3.4.2 extends Written / Text grading so an instructor can import a complete
multi-file LaTeX project ZIP—such as an Overleaf export—and grade its
application-compiled PDF through the existing Written interface.

## Highlights

### Canonical project ZIP ingestion

The original ZIP is preserved as immutable canonical submitted evidence. The
app validates and safely extracts the archive into a derived project store with
a manifest and source hashes rather than treating ZIP contents as trusted
filesystem input.

### Project discovery and explicit root resolution

The project resolver discovers LaTeX sources and complete root documents. A
single clear root can be chosen deterministically. If multiple complete roots
remain plausible, Written import shows **Choose project root** and requires an
explicit instructor selection.

### Whole-project compilation

The selected root is compiled together with the complete verified project,
including included source files and project assets, using the application's
existing restricted LaTeX compiler. The resulting PDF is exposed through the
same `compiled_pdf` grading contract as the established single-file `.tex`
workflow and appears in the normal Written viewer.

Compilation keeps shell escape disabled and applies the existing timeout,
source/output/log limits and restrictive TeX I/O settings. The restricted host
compiler is not represented as an OS/container sandbox.

### Persistent provenance and diagnostics

For each canonical project the app persists:

- original ZIP SHA-256;
- project manifest and source hashes;
- selected root and root-resolution method;
- compiler/options and compilation attempts;
- structured failure reason/log information;
- compiled-PDF SHA-256.

Compilation failures open instructor-facing diagnostics rather than reducing
the problem to an opaque exception.

### Recovery without re-import

A failed canonical project can be retried or, when multiple valid roots were
discovered, recovered by selecting another root without re-uploading the ZIP.
The chosen recovery root survives restart.

If a derived PDF disappears, it can be regenerated from the still-verified
canonical project. If the ZIP or extracted project fails integrity
verification, recovery is blocked instead of compiling altered bytes.

### Security and regression hardening

The release adds broad coverage for malformed archives, traversal/symlink/path
conflicts, archive resource limits, corrupt/non-ZIP input, ambiguous/no-root
projects, nested/Unicode/space-containing projects, compiler timeout/failure,
oversized output, tampering, shell-escape prevention, and existing Written /
Programming regression boundaries.

The v2.3.3 release acceptance fixture is now self-contained in temporary test
data and no longer depends on an untracked repository-root `fixtures/`
directory.

## Compatibility

v2.3.4.2 preserves:

- v2.3.2 canonical submission/history behavior;
- v2.3.3 programming autograding behavior;
- v2.3.4.1 Assessment Home and dual-mode navigation;
- existing single-file `.tex` → compiled-PDF Written grading;
- explicit PDF accommodation behavior;
- manual rubric grading and Written evidence/history workflows.

LaTeX project ZIP ingestion is a Written-mode feature. It does not execute
Python, modify Programming routing, merge programming scores into manual
rubrics, or add Canvas synchronization.

```bash
python -m unittest discover -s src/tests -p 'test_*_v2341.py' -v
python -m unittest discover -s src/tests -p 'test_*_v233.py'
python -m pytest src/tests -q
python -c "import src; assert src.__version__ == '2.3.4.2'; print(src.__version__)"
```

Complete `docs/v2.3.4.2_manual_acceptance.md` in the real PyQt application
before creating the release tag.
