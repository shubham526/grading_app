# v2.3.3 Manual Acceptance Checklist

Use this checklist after automated tests pass and before tagging v2.3.3.

## Preconditions

1. Docker Desktop / Docker Engine is running.
2. Build the dedicated runtime from the repository root:

   ```bash
   docker build \
     -t grading-app-python312-pytest:9.1.1 \
     docker/autograding/python312-pytest
   ```

3. Verify:

   ```bash
   docker run --rm --network none --pull=never \
     grading-app-python312-pytest:9.1.1 \
     python -c 'import pytest; print(pytest.__version__)'
   ```

   Expected: `9.1.1`.

4. Copy the committed fixture to a disposable location. From the repository root:

   ```bash
   rm -rf ~/Desktop/v2.3.3_autograding_acceptance
   cp -R fixtures/v2.3.3_autograding_acceptance \
     ~/Desktop/v2.3.3_autograding_acceptance
   ```

   Run all UI acceptance against the Desktop copy, not the repository fixture.

## 1. Load the disposable assessment

In the app:

1. Set **Grades + Evidence Folder** to:

   ```text
   ~/Desktop/v2.3.3_autograding_acceptance/workspace/assessments
   ```

2. Load rubric:

   ```text
   rubric/V233_AUTO1_programming.json
   ```

3. Confirm the grading header recognizes **1 of 1 questions**. It must not show `? questions`.
4. Load roster:

   ```text
   roster/roster.csv
   ```

5. Confirm six roster students appear: Aaron, Alice, Bob, Carol, Dave, Eve.

## 2. Import canonical Python submissions

Open **Import Submissions** and add the parent folder:

```text
submissions/
```

Confirm exactly five candidates map to:

```text
aaron
alice
bob
carol
dave
```

Eve intentionally has no submission.

Import all five.

Confirm:

- each imported student has active attempt 1;
- each canonical artifact is `main.py`;
- merely importing the submissions does not execute them;
- Eve still has no canonical submission.

## 3. Configure programming autograding

Open:

```text
Tools → Programming Autograding → Configure Autograder…
```

Import/select:

```text
autograder_bundle/
```

Use runtime:

```text
grading-app-python312-pytest:9.1.1
```

Click **Check Runtime** and confirm it reports available.

Save the configuration.

Close/reopen the configuration dialog and confirm the same immutable bundle/runtime remain selected.

## 4. Current-student grading — Alice

Select Alice and choose:

```text
Tools → Programming Autograding → Grade Current Submission
```

Confirm the pre-run dialog shows:

- Alice's stable student ID;
- attempt 1;
- the selected immutable bundle;
- the expected runtime image.

Run grading.

Confirm:

- the UI remains responsive while Docker runs;
- final score is **10 / 10**;
- `public_basic`, `hidden_zero`, and `hidden_negative` pass;
- public/hidden visibility is displayed correctly;
- the normal manual rubric score did **not** silently change.

## 5. History and rerun immutability

Open **Autograding History…** for Alice.

Confirm one run appears and opens successfully.

Grade Alice again with the same submission and bundle.

Confirm:

- history now shows two distinct run IDs;
- the first run still opens;
- neither run overwrote the other;
- both retain attempt 1 and score 10 / 10.

## 6. Bob — deterministic partial credit

Grade Bob.

Expected:

```text
public_basic      passed   4/4
hidden_zero       passed   3/3
hidden_negative   failed   0/3
final score                7/10
```

Confirm a normal hidden-test failure is not labeled an infrastructure failure.

## 7. Carol — student syntax error

Grade Carol.

Her source intentionally has invalid Python syntax.

Expected:

- student syntax/preflight error is reported;
- configured tests resolve to student-attributable `error` outcomes;
- final score is **0 / 10** under the default Commit-7 policy;
- the run is not mislabeled as Docker/container infrastructure failure.

## 8. Dave — per-test timeout

Grade Dave.

Expected:

```text
public_basic      passed    4/4
hidden_zero       passed    3/3
hidden_negative   timeout   0/3
final score                 7/10
```

Confirm this per-test timeout is attributable and therefore receives zero, rather than producing a run-level review state.

## 9. Student-safe hidden-test redaction

The normal results dialog is instructor-facing and may show hidden-test diagnostics.

Use automated tests and/or a student-safe report inspection to confirm student-facing output does **not** expose:

- raw hidden test IDs;
- pytest node IDs;
- hidden traceback;
- hidden stdout/stderr;
- grader bundle hashes;
- Docker environment/image provenance.

## 10. Batch preflight and normal batch grading

Open:

```text
Tools → Programming Autograding → Grade All Active Submissions…
```

Confirm:

- Aaron, Alice, Bob, Carol, and Dave are eligible;
- Eve is clearly skipped/ineligible because no active programming submission exists;
- no student is silently mapped or invented.

Start batch grading and allow it to finish.

Confirm per-student results match `EXPECTED_RESULTS.md` and each completed/review run appears in immutable history.

## 11. Cooperative batch cancellation

For a clean cancellation test, re-extract/copy a fresh fixture or simply start another batch. Aaron is first in the roster and intentionally takes long enough to make cancellation visible.

Immediately after starting the batch, click:

```text
Cancel After Current Student
```

Confirm:

- the currently running student is allowed to finish or hit its configured timeout;
- the GUI does not freeze;
- Docker cleanup completes;
- no next student begins after cancellation takes effect;
- remaining rows become `Cancelled`;
- cancelled students do not receive new persisted grading runs.

## 12. Verify persisted histories from the command line

From the grading-app repository root:

```bash
python ~/Desktop/v2.3.3_autograding_acceptance/tools/verify_persisted_history.py \
  ~/Desktop/v2.3.3_autograding_acceptance
```

The tool integrity-verifies every persisted latest run that exists and compares its score/test statuses with the fixture expectations.

## 13. Release regression gate

Run:

```bash
python -m unittest \
  src.tests.test_autograding_release_acceptance_v233 \
  src.tests.test_version -v
```

Then all v2.3.3 tests:

```bash
python -m unittest discover \
  -s src/tests \
  -p 'test_*_v233.py'
```

Then the complete repository suite:

```bash
python -m unittest discover -s src/tests
```

When pytest is available:

```bash
python -m pytest src/tests -q
```

Finally:

```bash
python -c "import src; assert src.__version__ == '2.3.3'; print(src.__version__)"
```

Do not tag v2.3.3 if any existing grading, submission, similarity, ABET, persistence, Docker, autograding, or UI regression fails.
