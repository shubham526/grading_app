# v2.3.2 Manual Acceptance Checklist

Use this checklist after automated tests pass and before tagging v2.3.2.

## Preconditions

- Start from a clean application workspace or a disposable copy of an existing assessment workspace.
- Load a rubric with a stable `assessment_id`.
- Load a roster containing at least three test students.
- Keep a copy of the test submission files outside `submission_evidence/`.

## 1. First-attempt written imports

Create three simple `.tex` files whose names contain stable roster IDs, for example:

```text
alice_PS1.tex
bob_PS1.tex
carol_PS1.tex
```

Use **Import Submissions** and confirm:

- all three candidates map to the intended roster students;
- all three preview as attempt 1;
- all three import successfully;
- supported LaTeX evidence opens in the normal grading workspace;
- `submission_evidence/canonical/<assessment>/<student>/index.json` exists;
- each student has exactly one canonical submission and it is active.

## 2. New attempt and immutability

Modify Bob's source bytes and import the same filename again.

Confirm:

- preview identifies a new attempt rather than an exact duplicate;
- Bob now has attempts 1 and 2 in **Submission History**;
- attempt 2 is active;
- attempt 1 remains selectable;
- attempt 1's original artifact and SHA-256 are unchanged;
- switching to attempt 1 changes the displayed grading evidence without deleting attempt 2.

## 3. Restart persistence

Close and reopen the application/workspace.

Confirm:

- Bob still has both attempts;
- attempt 2 remains active unless you explicitly changed it before closing;
- historical attempt selection still works;
- no new canonical attempt was created merely by reopening.

## 4. Exact duplicate behavior

Import Bob's unchanged attempt-2 source again.

Confirm:

- the preview marks it as an exact duplicate;
- it is not imported by default;
- no attempt 3 is created unless you explicitly force the duplicate as a new attempt.

## 5. Future LaTeX-project preservation

Select matching-stem files such as:

```text
alice_PS2.pdf
alice_PS2.zip
```

Confirm:

- they appear as one logical submission candidate;
- the committed submission has two canonical artifacts;
- the ZIP is not extracted in v2.3.2;
- the application reports the project handler as pending rather than pretending to grade it.

## 6. Programming preservation without execution

Import a `.py` file whose top-level code would create a sentinel file if executed.

Confirm:

- the Python artifact is committed and hashed;
- no sentinel file is created;
- no Python code is executed;
- the application reports the programming handler as pending for v2.3.3.

## 7. Ambiguous roster mapping

Create a filename that cannot uniquely identify one roster student.

Confirm:

- the preview requires manual mapping;
- no candidate is silently assigned to one of the ambiguous students;
- after manually selecting the intended roster record, the candidate becomes importable.

## 8. Legacy v2.2 compatibility

Open a workspace containing only the old v2.2 evidence structure.

Confirm:

- the old parsed submission still opens;
- canonical migration/linkage can occur without deleting the old evidence folder;
- reopening reuses the same canonical submission ID instead of creating a duplicate;
- existing scores, feedback, rubric state, ABET data, and similarity behavior are unchanged.

## 9. Assessment JSON contract

Save an assessment after a canonical submission is loaded.

Confirm the submission-supporting top-level fields remain exactly:

```text
submission_meta
extracted_answers
```

`submission_meta` may now contain canonical provenance such as `submission_id`, `assessment_id`, `attempt`, `source_system`, and `artifact_ids`.

## 10. Release gate

Run the complete project test suite in the production environment. Do not tag v2.3.2 if any existing grading, scoring, similarity, ABET, parser, persistence, or UI regression fails.

Recommended final commands:

```bash
python -m unittest discover -s src/tests
```

and, when pytest is available:

```bash
python -m pytest src/tests -q
```

Then verify:

```bash
python -c "import src; assert src.__version__ == '2.3.2'; print(src.__version__)"
```
