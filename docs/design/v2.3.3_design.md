# v2.3.2 Design — Overleaf / LaTeX Project ZIP Ingestion

**Release:** `v2.3.2 — Overleaf / LaTeX Project ZIP Ingestion`  
**Repository:** `grading_app`  
**Status:** Design specification  
**Depends on:** v2.2.x LaTeX/PDF ingestion and v2.3.x downstream grading/similarity

## 1. Purpose

v2.3.2 extends the existing LaTeX/PDF ingestion workflow so that a student may submit a complete Overleaf project instead of a single `.tex` file.

The recommended standard submission becomes:

```text
lastname_firstname_PS1.pdf
lastname_firstname_PS1.zip
```

The ZIP is the complete Overleaf source project. The PDF is the student's compiled rendering.

The design goal is to preserve a reproducible source submission while reusing the current question extraction, grading, ABET, and similarity pipelines downstream.

## 2. Motivation

A single `.tex` file stops being self-contained once a project contains files such as:

```text
main.tex
macros.tex
answers/
  q1.tex
  q2.tex
figures/
  graph.pdf
  diagram.png
references.bib
```

A full source ZIP preserves the actual project dependency tree and is more robust than asking students to manually extract only one `.tex` file.

## 3. Scope

### In scope

v2.3.2 shall:

1. Accept an Overleaf-style source ZIP.
2. Pair the source ZIP with the submitted PDF.
3. Safely extract the ZIP into an isolated working directory.
4. Require a deterministic project entry point.
5. Reuse the existing v2.2 LaTeX parser after entry-point resolution.
6. Preserve the original ZIP as evidence.
7. Preserve the submitted PDF as rendered evidence.
8. Record project manifest and hashes.
9. Persist source-project provenance in saved assessments.
10. Keep `.tex + .pdf` support for backward compatibility.
11. Support multi-file LaTeX projects.
12. Add validation, UI feedback, tests, and synthetic acceptance fixtures.

### Out of scope

v2.3.2 shall not:

- change grading logic,
- change ABET scoring,
- change similarity algorithms,
- add OCR,
- add LLM grading,
- repair broken LaTeX automatically,
- rewrite student source,
- silently guess among several plausible main files,
- use the Overleaf API,
- execute arbitrary scripts from a student project.

## 4. Submission Contract

The course-provided Overleaf template should require a root:

```text
main.tex
```

Students may add subfiles, images, bibliographies, and directories, but should not rename or move the root `main.tex`.

Recommended student instructions:

> Submit both the compiled PDF and the complete Overleaf source ZIP. Do not manually remove files from the source ZIP. Do not rename or move the root `main.tex`.

## 5. Main-Document Resolution

Deterministic rule:

```text
ZIP root contains ./main.tex
    → valid source project

ZIP root does not contain ./main.tex
    → ingestion error
```

The app should not guess among arbitrary `.tex` files.

A nested `main.tex` does not satisfy the contract if root `main.tex` is absent.

## 6. High-Level Architecture

```text
student.zip
    ↓
archive validation
    ↓
safe extraction
    ↓
project manifest + hashes
    ↓
root main.tex validation
    ↓
LaTeXProjectSource
    ↓
existing v2.2 LaTeX ingestion
    ↓
ParsedSubmission
    ↓
grading / ABET / similarity
```

ZIP-specific behavior stays upstream. Downstream grading code should continue consuming the same parsed question-level submission abstraction.

## 7. Proposed New Model

```python
@dataclass
class LaTeXProjectSource:
    archive_path: Path
    extraction_dir: Path
    main_tex_path: Path
    project_files: list[str]
    archive_sha256: str
    file_hashes: dict[str, str]
    total_uncompressed_bytes: int
```

Optional manifest entry:

```python
@dataclass
class ProjectManifestEntry:
    relative_path: str
    size_bytes: int
    sha256: str
    file_type: str
```

Portable metadata must use relative project paths rather than user-machine absolute paths.

## 8. Safe ZIP Extraction

Student ZIPs are untrusted input.

Do not blindly call `ZipFile.extractall()`.

Reject archives containing:

- `../` path traversal,
- absolute paths,
- Windows-drive absolute paths,
- symlinks,
- special/device files,
- paths escaping the extraction root,
- duplicate conflicting paths,
- excessive file count,
- excessive total uncompressed size,
- excessive individual files,
- malformed ZIP structure.

Suggested configurable safeguards:

```text
max archive size             50 MB
max uncompressed size       250 MB
max file count             1000
max single extracted file   50 MB
```

These are application safety defaults, not course policy.

## 9. Extraction Layout

Each student project should be isolated:

```text
evidence/
  alice/
    source_project/
      main.tex
      ...
```

Extraction directories should not be reused in a way that can leave stale files from earlier submissions.

## 10. Project Compilation

Compile from the project directory:

```text
working directory = source_project/
entry point        = main.tex
```

This allows normal relative project dependencies:

```latex
\input{answers/q1.tex}
\includegraphics{figures/tree.pdf}
\bibliography{references}
```

The app must compile the project rather than copy `main.tex` into another directory and compile it in isolation.

## 11. Submitted PDF Semantics

The submitted PDF remains the student's rendered evidence.

Local project compilation is useful for:

- validation,
- reproducibility,
- parsing,
- diagnostics.

A local compilation result should not silently replace the student's submitted PDF.

## 12. PDF + ZIP Pairing

Normal expected pair:

```text
smith_alice_PS1.pdf
smith_alice_PS1.zip
```

Possible statuses:

```text
complete_pair
missing_pdf
missing_source_zip
duplicate_pdf
duplicate_source_zip
```

Pairing should reuse the application's existing student/submission identity logic where possible.

Legacy `.tex + .pdf` mode remains supported.

## 13. Provenance

Persist project provenance similar to:

```json
{
  "source_used": "latex_project_zip",
  "submission_mode": "latex_project",
  "authoritative_source": "latex_project_zip",
  "rendered_source": "submitted_pdf",
  "project": {
    "main_tex": "main.tex",
    "archive_sha256": "...",
    "project_file_count": 7,
    "total_uncompressed_bytes": 184203,
    "project_files": [
      "main.tex",
      "macros.tex",
      "answers/q1.tex",
      "figures/tree.pdf",
      "references.bib"
    ]
  }
}
```

Large per-file hash manifests may be stored once in evidence metadata rather than duplicated into every record.

## 14. Similarity Implications

v2.3.2 should preserve distinct exact-match signals:

```text
archive SHA-256
main.tex SHA-256
normalized question text
```

These mean different things and should remain distinguishable.

Examples:

- identical ZIP → exact project identity,
- different ZIP but identical `main.tex` → exact root-source identity,
- different source but identical extracted answer → normalized-text identity.

No similarity algorithm needs to be redesigned for this release.

## 15. UI Changes

Submission UI should recognize:

```text
LaTeX project ZIP
```

and display:

```text
Submitted PDF
Source ZIP
Main document
Project file count
Validation status
```

Actionable errors should include:

```text
Missing root main.tex
Unsafe archive path
Archive exceeds configured limit
No matching PDF
Duplicate source ZIP
LaTeX project compilation failed
```

A project-manifest viewer is desirable.

## 16. Backward Compatibility

Continue supporting:

```text
.pdf + .tex
PDF accommodation
saved assessment JSON
```

Suggested source values:

```text
latex
latex_project_zip
pdf
saved_assessment
```

Existing downstream grading, ABET, and v2.3.x similarity code should not acquire ZIP-specific logic.

## 17. Error Codes

Recommended structured errors:

```text
UNSAFE_ARCHIVE_PATH
ARCHIVE_TOO_LARGE
ARCHIVE_FILE_LIMIT_EXCEEDED
MISSING_MAIN_TEX
INVALID_MAIN_TEX
SOURCE_PDF_PAIR_MISSING
LATEX_PROJECT_COMPILE_FAILED
```

Failed ingestion must not be persisted as a successful parsed submission.

## 18. Testing

All tests must be offline and synthetic.

### Archive security

Test:

- valid project,
- traversal path,
- absolute path,
- symlink,
- too many files,
- uncompressed-size limit,
- duplicate path,
- malformed ZIP,
- empty ZIP.

### Project structure

Test:

- root `main.tex`,
- `\input` subfiles,
- figures,
- `.bib`,
- multiple `.tex` files,
- missing root `main.tex`,
- nested-only `main.tex`,
- correct compilation working directory.

### Pairing

Test:

- PDF + ZIP,
- missing PDF,
- missing ZIP,
- duplicate PDF,
- duplicate ZIP,
- legacy PDF + TEX.

### Provenance

Verify:

- archive hash,
- root main file,
- project manifest,
- authoritative source,
- submitted PDF provenance.

### Regression

Run the complete repository test suite after the focused tests.

## 19. Manual Acceptance Fixture

The v2.3.2 fixture should include:

1. simple single-file project,
2. multi-file project using `\input`,
3. project with figure and bibliography,
4. project missing root `main.tex`,
5. deliberately unsafe ZIP.

Acceptance should verify pairing, safe extraction, project parsing, question extraction, saved provenance, downstream grading, and similarity review.
