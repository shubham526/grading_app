# v2.3.3 Design — Fall 2026 CS 2500 ABET Evidence & Course Alignment

**Release:** `v2.3.3 — Fall 2026 ABET Evidence & Course Alignment`  
**Repository:** `grading_app`  
**Status:** Design specification  
**Application scope:** Problem Sets and Exams only  
**Primary course:** CS 2500 Algorithms, Fall 2026  
**Depends on:** v2.0 ABET infrastructure, v2.1 question-centric grading, v2.2/v2.3.2 submission ingestion

## 1. Purpose

v2.3.3 adapts the grading app's existing ABET infrastructure to the finalized Fall 2026 CS 2500 course design.

This grading app is deliberately limited to:

```text
PS1
PS2
PS3
PS4
PS5
PS6
Exam 1
Exam 2
```

It does **not** grade or manage:

```text
Knowledge Checks
Workshops
attendance
participation
CS 2580
```

The release goal is:

> Grade Problem Sets and Exams once while automatically preserving the criterion-level evidence required for Fall 2026 SLO and ABET reporting.

## 3. Core Design Principles

### 3.1 Criterion-level evidence

The atomic evidence unit is:

```text
student
× assessment
× question
× rubric criterion
```

Whole-assignment percentage is not an acceptable substitute for a selected ABET criterion.

### 3.2 Course grading and ABET rating are separate

A criterion may simultaneously have:

```text
course score:
  8 / 10

ABET rating:
  Adequate
```

The app must store both explicitly.

### 3.3 Outcome mapping and official ABET inclusion are separate

A criterion may be aligned to:

```text
SLO2.4
SO1
SO2
```

while still having:

```text
abet_counted = false
```

Mapping answers:

> What does this criterion measure?

`abet_counted` answers:

> Is this criterion one of the selected official ABET measures?

### 3.4 Historical reproducibility

Do not overwrite the old CS 2500 outcome profile.

Add a versioned Fall 2026 profile so historical reports continue to reproduce under their original profile IDs.

## 4. Scope

### In scope

v2.3.3 shall support:

1. Fall 2026 SLO identifiers/descriptions.
2. Fall 2026 SLO → Program SO crosswalk.
3. Stable question IDs.
4. Stable criterion IDs.
5. Criterion → SLO mapping.
6. Criterion → SO mapping.
7. Independent `abet_counted`.
8. Department-approved rubric/category references.
9. Explicit four-level ABET ratings.
10. Separate course score and ABET performance level.
11. Evidence status.
12. Assignment-level evidence reporting.
13. Semester aggregation across PS/exam evidence.
14. `% Adequate + Excellent`.
15. 75% attainment target.
16. Criterion-level master evidence export.
17. Evidence/alignment audit.
18. Fall 2026 PS/exam rubric templates.
19. Synthetic acceptance fixtures.

### Out of scope

v2.3.3 shall not:

- grade Knowledge Checks,
- grade Workshops,
- manage attendance,
- grade CS 2580,
- import CS 2580 evidence,
- claim CS 2500 pseudocode is implementation evidence,
- calculate the complete program-level SO2 story,
- replace the department-approved rubrics,
- infer ABET ratings from whole-assignment grades,
- require every PS/exam criterion to be ABET evidence,
- force every department-rubric category onto every artifact,
- add LLM grading.

## 7. `counted` vs `abet_counted`

This distinction is mandatory.

### Existing field

```text
counted
```

means:

> This question/criterion contributes to the student's course-grade calculation.

This may be affected by best-N or selected-question grading.

### New field

```text
abet_counted
```

means:

> This criterion is selected as official ABET evidence.

These fields must never be aliases.

Normal example:

```text
counted = true
abet_counted = false
```

## 9. Separate Course Score and ABET Rating

Recommended saved criterion:

```json
{
  "id": "EX1_Q4_PROOF_LOGIC",
  "question_id": "Q4",

  "points_awarded": 5,
  "points_possible": 6,

  "course_outcomes": ["SLO1.2"],
  "program_outcomes": ["SO1"],

  "counted": true,
  "abet_counted": true,

  "abet_result": {
    "department_rubric_id": "theory",
    "department_category_id": "logic",
    "performance_level": "adequate",
    "evidence_status": "valid"
  }
}
```

The authoritative ABET rating must not be silently derived from `points_awarded / points_possible`.

A score-derived suggestion could be considered in a later release, but it is not the official evidence model.

## 10. Evidence Status

Supported states:

```text
valid
missing
excused
not_applicable
```

### Meaning

`valid`
: Usable evidence exists and has a performance level.

`missing`
: Required evidence is absent.

`excused`
: Evidence is absent for an approved reason and is excluded from the normal valid-evidence denominator.

`not_applicable`
: The selected department category does not apply to this artifact.

### Official aggregation filter

At minimum, official attainment should aggregate only:

```text
abet_counted == true
AND
evidence_status == valid
```

The exact departmental treatment of `missing` and `not_applicable` should be configurable/documented.

## 15. Official ABET Aggregation

Point-percentage aggregation can remain for ordinary course/SLO analytics.

Official ABET attainment should aggregate explicit performance levels.

Example:

```text
Excellent              18
Adequate               55
Needs Improvement      16
Inadequate              7
--------------------------------
Valid evidence          96
Adequate + Excellent    73
Attainment              76.04%
Target                  75%
Status                  Met
```

Formula:

```text
attainment_percentage =
    (N_adequate + N_excellent)
    / N_valid_evidence
    * 100
```

Do not infer the official tally from whole-assignment percentages.

## 16. Multiple Measures for One SO

A student may have several ABET-counted criteria aligned to one SO.

Recommended reporting model:

```text
Each selected department-rubric category is a separate measure.
```

For example:

```text
SO1
  Exam 1 / Algorithms Mechanics
  Exam 1 / Theory Logic
  Exam 2 / Algorithms Application
```

The report may also provide an SO rollup, but it must document how that rollup is computed.

Do not average ordinal labels numerically without an explicit policy.

## 22. Department Rubric Application Rules

Preserve these rules:

1. Write the assessment question from the SLO/evidence need first.
2. Select only department-rubric categories genuinely elicited by that question.
3. Do not force every category onto every artifact.
4. Preserve the four official performance levels.
5. Assignment-specific descriptors may clarify a category.
6. Course points and ABET ratings stay separate.
7. Only selected valid evidence enters official attainment.

For the Algorithms rubric, `Experimental Analysis` should not be forced onto theoretical artifacts that do not elicit experimental work.

The app may support `not_applicable`; departmental policy determines when it may be used.

## 23. Backward Compatibility

Existing schema 2.0 rubrics/assessments must continue to load.

If old data lacks:

```text
question_id
abet_counted
abet_result
```

use conservative defaults:

```text
abet_counted = false
```

Do **not** convert every historically mapped criterion into official ABET evidence.

Existing `counted` continues to mean course-grade counted.

Historical reports continue using their original profile IDs.

## 30. Resulting Instructor Workflow

Before grading:

```text
author assessment
    ↓
assign stable question IDs
    ↓
create rubric criteria
    ↓
map SLOs/SOs
    ↓
select official ABET criteria
    ↓
attach department rubric/category
```

During grading:

```text
grade criterion normally
    ↓
record course points
    ↓
if ABET-counted:
    record explicit performance level
```

At reporting:

```text
semester ABET report
    ↓
aggregate only selected valid evidence
    ↓
performance-level distribution
    ↓
% Adequate + Excellent
    ↓
75% target status
    ↓
master evidence export
```

The intended end state is that ABET evidence collection becomes a by-product of normal PS/exam grading rather than a separate retrospective reconstruction task.
