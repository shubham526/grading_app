# v2.3.4.2 Manual Acceptance

v2.3.4.2 adds a user-facing Overleaf / multi-file LaTeX project ZIP workflow to
Written grading. Automated tests are required, but the final release also needs
manual PyQt acceptance of the real import/view/restart path.

Use only disposable synthetic data for release acceptance.

## 1. Automated release gate

From the repository root:

```bash
python -m unittest discover -s src/tests -p 'test_*_v2342.py' -v
python -m unittest discover -s src/tests -p 'test_*_v2341.py' -v
python -m unittest discover -s src/tests -p 'test_*_v233.py'
python -m pytest src/tests -q
python -c "import src; assert src.__version__ == '2.3.4.2'; print(src.__version__)"
```

All non-optional tests must pass before tagging.

## 2. Assessment Home and Written entry

Launch the application. On **Assessment Home**:

1. load a synthetic rubric;
2. load the matching synthetic roster;
3. choose a fresh Grades + Evidence workspace;
4. click **Open Written Grader**.

Confirm Programming mode does not need to be entered and no Programming
controls appear in the Written grading workspace.

## 3. Normal multi-file Overleaf ZIP

Import a synthetic ZIP containing at minimum:

```text
main.tex
macros.tex
answers/q1.tex
answers/q2.tex
```

Prefer also including a bibliography and figure asset so the release check
resembles a real Overleaf export.

Confirm:

- the ZIP maps to the intended roster student;
- there is one deterministic root (`main.tex`);
- no root-selection prompt appears;
- canonical import succeeds;
- the complete project compiles;
- the compiled PDF appears in the normal left-hand Written viewer;
- the rendered answers correspond to the included child files;
- normal rubric grading on the right remains usable;
- saving the grade works normally.

## 4. Ambiguous-root project

Import a second synthetic ZIP containing two complete documents, for example:

```text
main.tex
report.tex
```

Confirm:

- the preview status is **Choose project root**;
- **Select LaTeX Project Root** appears before canonical commit;
- neither root is silently preselected;
- selecting one root compiles that document;
- cancelling the root dialog aborts that import before canonical commit.

## 5. Structured compilation diagnostics

Using an ambiguous project, deliberately choose a root containing invalid
LaTeX while another discovered root is valid.

Confirm the canonical import remains present but evidence preparation opens
**LaTeX Project Diagnostics**. Verify the dialog shows the failed root,
`pdflatex`, and a structured reason code, and enables the available actions:
**View Compilation Log**, **Open Source Project**, **Retry Compilation**, and
**Choose Different Root**.

Choose the valid alternative root and confirm recovery completes without
re-importing the ZIP. The recovered PDF must become the active grading visual.

## 6. Restart persistence

Close the application completely. Relaunch it with the same rubric, roster,
and workspace.

Confirm the recovered canonical attempt still uses the instructor-selected
root and the same compiled grading PDF without asking for root selection again.
Previously saved manual grading state must remain available through the normal
Written workflow.

## 7. Missing derived PDF regeneration

With the app closed, delete only a disposable fixture's derived LaTeX-project
compiled PDF and the corresponding parsed-evidence cache. Do not alter the
canonical ZIP, manifest, or extracted project.

Reopen the same assessment/workspace and confirm the project re-verifies and
the missing compiled PDF is regenerated without re-importing the source ZIP.
Provenance should retain the earlier attempt and append the regeneration
attempt with a compiled-PDF SHA-256.

## 8. Integrity-blocked recovery

Using a separate disposable failed fixture, alter one file in the canonical
**derived extracted project** after its initial compilation failure. Then click
**Retry Compilation** in the still-open diagnostics flow.

Confirm:

- status becomes `integrity_failed`;
- the reason code is `latex_project_integrity_failure`;
- the detail reports a manifest/size/hash mismatch;
- **Retry Compilation** is disabled;
- **Choose Different Root** is disabled;
- the UI explains that recovery is blocked because canonical project integrity
  verification failed.

Do not repair or reuse that intentionally contaminated fixture attempt.

## 9. Legacy Written regression

Using fresh synthetic data, verify:

- a normal single `.tex` submission still compiles and displays its PDF;
- an explicit PDF accommodation still follows the existing accommodation flow;
- question navigation, rubric scoring, save/resume, similarity/history, and
  other established Written features still behave normally.

## 10. Programming isolation

Return to **Assessment Home**, enter Programming, and verify the v2.3.4.1
Programming dashboard is unchanged. A Written LaTeX ZIP must not alter Python
submission routing or autograding behavior.

## 11. Final release checks

Run the complete repository suite once more:

```bash
python -m pytest src/tests -q
```

Then:

```bash
python -c "import src; print(src.__version__)"
```

Expected:

```text
2.3.4.2
```

Do not tag the release if archive safety, compilation safety, canonical
integrity, restart persistence, existing Written behavior, or Programming
regressions fail.
