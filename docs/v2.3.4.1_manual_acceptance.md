# v2.3.4.1 Manual Acceptance

Automated tests are necessary but not sufficient for this release because
v2.3.4.1 changes the application's top-level navigation and workspace
boundaries. Complete this checklist in the real PyQt application before tagging
the release.

Use disposable/synthetic assessment data. Do not use real student submissions
for release acceptance.

## 1. Automated gate first

From the repository root:

```bash
python -m unittest discover -s src/tests -p 'test_*_v2341.py' -v
python -m unittest discover -s src/tests -p 'test_*_v233.py'
python -m pytest src/tests -q
python -c "import src; assert src.__version__ == '2.3.4.1'; print(src.__version__)"
```

All non-optional tests must pass before manual acceptance continues.

## 2. Startup / Assessment Home

Launch the application.

Confirm:

- the first page is **Assessment Home**;
- **Load Rubric**, **Load Roster**, and **Choose Workspace** are visible;
- **Open Written Grader** and **Open Programming Grader** are initially disabled;
- no grading mode is inferred automatically.

Complete the three shared setup steps.

Confirm after each step that its status updates, and after all three steps both
mode-entry buttons become enabled.

Loading the rubric from Assessment Home must not automatically open the
Written-only Grading Configuration dialog.

## 3. Direct Programming entry

From Assessment Home, click **Open Programming Grader** without first entering
Written.

Confirm:

- Programming opens successfully using the shared rubric/assessment, roster,
  and workspace;
- the dashboard contains exactly the expected primary programming actions:
  **Configure Autograder**, **Import Submissions**, **Check Runtime**,
  **Grade Selected**, **Grade All**, and **Run History**;
- the Written submission/rubric split pane, question-centric controls, and PDF
  viewer controls are not displayed.

## 4. Programming data and runtime

Using a known synthetic programming assignment:

1. Import canonical Python submissions.
2. Confirm roster-only students remain **No submission**.
3. Configure a matching immutable autograder bundle.
4. Click **Check Runtime** with Docker running.
5. Confirm the GUI remains responsive and the runtime reports available.

## 5. Grade Selected

Grade at least:

- one fully correct submission;
- one submission with a normal test failure;
- one syntax/student error;
- one per-test timeout if available in the synthetic fixture.

Confirm:

- the app does not freeze or crash;
- dashboard rows refresh after each run;
- Latest Result follows the selected student;
- **View Results** opens the persisted run;
- student errors/timeouts use the established v2.3.3 scoring semantics;
- infrastructure failures do not silently become student zeros.

## 6. Immutable rerun history

For one graded student, use **Grade Again**.

Confirm:

- a new immutable run is created;
- the previous run remains available;
- **Run History** / **View History** shows both runs rather than replacing the
  first.

## 7. Active-attempt isolation

For a student with a graded Attempt 1, import a corrected Attempt 2.

Before grading Attempt 2, confirm the Programming table shows:

```text
Attempt 2
Not graded
Score —
```

The old Attempt-1 score must not appear as the current Attempt-2 score.

Grade Attempt 2 and confirm its own result appears while prior runs remain in
history.

## 8. Grade All

Run **Grade All** on the synthetic roster.

Confirm:

- eligible active submissions are graded;
- missing/ineligible submissions are not fabricated;
- one student's failure does not abort the batch;
- completed runs appear in immutable history.

If practical, start another batch and test **Cancel After Current Student**.
Confirm no next student begins after cooperative cancellation takes effect.

## 9. Return to Assessment Home

Use **File → Assessment Home…**.

Confirm:

- the common rubric/assessment remains configured;
- the roster remains loaded;
- the Grades + Evidence workspace remains selected;
- both grading-mode entry buttons remain available.

## 10. Written workspace isolation

Click **Open Written Grader**.

Confirm:

- the established Written grading UI still appears and behaves normally;
- the old visible **Load Rubric** button is not shown;
- **Written Setup** does not contain **Choose Workspace…** or **Load Roster…**;
- **Written Setup** still contains Written-only actions such as **Load Reference
  Solution…** and **Add PDF Accommodation…**;
- Written **Tools** does not contain a Programming Autograding submenu;
- Written grading configuration, rubric scoring, student/question navigation,
  save/resume, submission evidence, similarity review, and history continue to
  work.

## 11. Unsaved Written transition guard

Make an unsaved Written grading change and choose **File → Assessment Home…**.

Confirm the **Save / Discard / Cancel** safety prompt appears.

At minimum, choose **Cancel** once and verify the app stays in Written mode with
the unsaved state intact. Then verify Save or Discard behaves according to the
existing Written workflow.

## 12. Active Programming transition guard

Return to Programming. Start **Check Runtime**, **Grade Selected**, or a batch
operation and immediately choose **File → Assessment Home…** while that
operation is active.

Confirm:

- the transition is blocked;
- the app explains that Programming grading is in progress;
- once the worker/batch finishes, returning to Assessment Home succeeds.

## 13. Repeated mode switching

Exercise:

```text
Assessment Home
→ Written / Text
→ Assessment Home
→ Programming
→ Assessment Home
→ Written / Text
```

Confirm the shared assessment, roster, and workspace persist and neither
workspace is reconstructed in a way that loses its in-memory state.

## 14. Final release checks

Run the complete repository test suite again after manual acceptance:

```bash
python -m pytest src/tests -q
```

Then verify:

```bash
python -c "import src; print(src.__version__)"
```

Expected:

```text
2.3.4.1
```

Do not tag v2.3.4.1 if any existing Written regression, programming-autograding
regression, state transition, persistence, hidden-test redaction, or Docker
safety regression fails.
